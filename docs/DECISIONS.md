## 2026-11-15 V2 第 1 步设计决策

用户“开始第一步”批准架构与文档工作；以下为本步形成的设计决策，业务实现仍需后续逐步批准。完整说明见 [V2_STARTUP_DESIGN.md](V2_STARTUP_DESIGN.md)。

| 编号 | 设计决策 | 原因与验收约束 |
|---|---|---|
| V2-D01 | 保持模块化单体，增加四个领域模块 | 复用现有 Python、认证、模板和事务；不引入微服务/队列/多 Agent |
| V2-D02 | ai_gateway 是唯一模型与密钥入口 | 默认/模块指定模型、受控 Adapter、结构校验、用量未知不伪造 |
| V2-D03 | 服务端认证加密、环境主密钥、只返回掩码 | 缺钥拒绝 AI 操作；轮换可追踪；不输出至日志或导出 |
| V2-D04 | SSRF 检查延伸至实际连接 | 防重定向、IPv4/IPv6 等价表示和 DNS 重绑定；不只校验保存时字符串 |
| V2-D05 | 第 5 步先建推荐批次及基础四色评价 | 第 6 步复用同结果，避免依赖倒置和跨页面矛盾 |
| V2-D06 | 状态/批次原子发布，代次与内容指纹检查 | 事务外 AI、失败保留、旧请求不覆盖新请求、目标变更标过期 |
| V2-D07 | 手动保存新状态与正常刷新失败分开 | 前者清空当前批次显示未评估；后者保持上次完整状态/批次 |
| V2-D08 | 类型与 UUID 定位、四个边界复查目标 | 页面/消息/生成/确认不信任客户端目标正文和 AI ID |
| V2-D09 | 草稿确认后才调用原领域写入服务 | 精确幂等、相似重复提示、共享事务和原事件；AI 不掌管完成/奖励 |
| V2-D10 | 保持一层子任务与重复任务限制 | 不合法继续细分时用关联行动清单；清单不计经验/金币或任务进度 |
| V2-D11 | 缺失字段标未知、模型估计标来源 | 不把时长/依赖/精力评分伪称现有事实；颜色适配与优先级排序分开 |
| V2-D12 | V2 承接原 2.1/2.2 与 2.6 状态子集 | 不重复开发 AI；其他角色、复盘和通用对话仍在原路线待审批 |

第 2 步须冻结供应商测试配置、加密库/出站实现及超时预算；第 5 步冻结规则阈值、缓存和分析上限；第 6 步冻结旧页面同步间隔；第 9 步验证私密导出范围。无可靠计量不编造工时或 Token；本步未调用项目模型 API。

下文是历史阶段决策。旧“尚未决定”项目若已有后续实施记录，按最新记录解释；V2 设计完成不表示新功能已经实现。

导出 ZIP 同时提供 JSON 与 CSV，属于数据导出而非自动可导入的数据库备份；误删恢复复用各领域约束。


## 阶段 1.8 更新

首页待办定义为用户时区今天到期或已逾期、未完成且可用的任务；没有截止日期或未来到期的任务仍可在副本列表查看。


## 阶段 1.7 更新

用户决定为此前仍处于完成状态的任务补发一次，包括已软删除任务。默认每个完成轮次 10 XP、5 金币，规则可改；每 100 XP 一级，父子任务各自计奖。撤销完成按原额冲正，删除不自动撤销。


## 阶段 1.6 更新

时间汇总以记录在用户时区的开始日归属，跨午夜整条计入开始日而非分摊；页面明确显示此规则。修改计时记录不改原始会话，保留变更前后快照。


## 阶段 1.5 更新

倒计时到时后显示零并等待用户明确结束；有效时长最多记至目标值。正计时关闭或刷新页面不会自动结束。异常中断时允许用户结束前确认较短的有效秒数，原会话和区间保留。


## 2026-11-10 阶段 1.4 更新

1.4 采用一层子任务；重复任务为无子任务的根任务，完成时生成下一期。主线按有效末级任务等权，空任务回退里程碑。撤销完成保留已生成的下一期。计时与奖励留待 1.5 和 1.7。

## 当前不采用的方案

- 微服务、Kafka、Redis 队列：当前闭环不需要这些设施；未来按证据评审。
- 用 SQLite 或浏览器存储替代真实 PostgreSQL 验收：不满足用户当前要求。
- 以 AI 判断主线完成度或直接覆盖任务：违背可验证规则与确认机制。
- 一开始创建全部业务表与空模块：增加后续调整成本。

未决项不应被悄悄视为默认批准；到相应模块提案中给出建议及影响，由用户确认。
