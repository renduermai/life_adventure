# 杂念模块使用与数据说明

打开项目并登录，左侧选择「杂念」。在输入框写下想法，点击「发送」。发送只保存原文；相同文字在不同时间分别发送，分别计为一次。左侧在首次归类前按时间显示原文，点击可在右侧查看完整内容。删除需要确认，删除后不再显示；原文软删除保留在数据库记录中。

需要整理时点击「AI 一键归类」。页面提示归类将发送当前账号的有效原文给灵石区配置的模型，可能产生费用；只有这次显式点击会调用模型。先在「灵石区」配置默认模型。归类结束后左侧展示类别、具体主题及出现次数；同一类别可有多个主题。次数来自数据库中当前未删除的原文。点击主题，右侧按时间倒序分页展示完整历史原文，右侧可独立滚动。新写的想法进入「待归类」，信息不足的想法进入「待确认」；再次归类会尝试合并。原文与模型生成的主题分开保存，模型失败会保留上次成功主题。刷新或重启后重新读取数据库结果。

如果提示模型超时、JSON/字段校验失败或编号错误，可稍后重试；成功结果仍可查看。相同原文和同一模型配置及提示词版本会复用已保存结果。记录较多且超过同步预算时会明确失败，旧版保留；不会截断原文或发布部分分类。模型分类可能不完全符合个人理解。

## 数据与备份

当前数据库版本为 `0019_distraction_classification`。原文保存在 `distraction_notes`，分类版本、主题和关联分别保存在 `distraction_classification_runs`、`distraction_topics` 和 `distraction_memberships`。这些表只通过用户账号归属，不写入主线、副本、启动状态、金币或经验。日志不保存 API Key 或完整原文。

现有应用「数据与恢复」导出使用固定模型名单，**尚不包含杂念四张表**，不能当作杂念备份。请在数据库管理端执行完整 PostgreSQL 备份，至少保留这四张表、`users` 以及迁移版本；备份文件包含私人原文，应限制访问并加密保存。恢复时在独立数据库验证表行数、原文、分类版本和主题计数，再切换正式连接。不要在真实库执行 Alembic downgrade，因为会删除分类或原文表。应用版本与数据库迁移版本必须匹配；旧代码直接连接0019时可能返回 readiness 503。

## 验收操作

1. 登录并保存两条同一担忧的不同表达，再保存一条不同担忧；刷新，确认三条原文完整且时间按账号时区展示。
2. 点击 AI 一键归类，确认主题可点击，右侧显示对应原文，次数总和与有效记录数一致；如模型认为内容不足，可在「待确认」查看。
3. 保存一条新记录，确认出现在「待归类」；再次归类后检查次数，重复点击且内容不变时不会增加次数。
4. 删除一条原文，确认所在主题次数减少；删除最后一条时主题隐藏。刷新及重启应用后检查结果仍在。
5. 用另一个账号登录，确认无法看到前一个账号的原文或分类。模型调用可能产生费用。

运行命令：`.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log`。浏览器打开 `http://127.0.0.1:8000/distractions`。
