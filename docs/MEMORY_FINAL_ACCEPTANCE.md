## 本轮修复

1. 物品保存期间，列表操作和新增仍可触发，可能改变上传后的编辑目标。统一禁用操作并在打开编辑时检查busy。
2. 物品/心愿筛选失败时，可能把上一类别卡片留在新筛选下。切换时先清空旧列表并显示加载，失败后保持错误和重读入口；已消失类别保留明确的空筛选标签。
3. 物品选择新图片后勾选移除时仍可能提交该文件；改变图片后创建请求编号也可能沿用。补齐移除时清空文件和预览，以及重新选择时重置提交编号。

新增故障注入浏览器测试实际执行后端上传/替换接口、检查原图片与输入保留、成功替换后原资产撤销访问，以及筛选503时不显示旧卡片。没有新增数据库迁移、没有修改价格或联系评分规则。

## 使用与恢复

日常双击桌面启动快捷方式，或在项目根目录执行：

```powershell
.\Start-AdventureCamp.cmd
```

访问 http://127.0.0.1:8000/shining-memories ，登录现有账号。人物说明见MEMORY_PEOPLE.md，心愿价格和分类见MEMORY_WISHES.md，图片配置及加密备份工具见SHINING_MEMORIES.md。

完整恢复需要代码/依赖/迁移、匹配的应用数据库备份、独立图片对象备份及单独保管的环境配置/解密密钥。既有JSON/CSV导出不是全数据库备份，未覆盖本模块全部表；Supabase数据库备份也不包含图片对象。当前电脑上的加密迁移检查点只用于本机回滚保障，不算异地副本。

图片工具restore只向独立空私有Bucket恢复并核对对象，不恢复正式数据库或自动切换线上Bucket。灾难恢复应先在隔离环境恢复匹配数据库，再核对资产ID、所属用户、对象路径及哈希，确认后再切换。不要用正式数据库降级删表来代替恢复。

## 关闭剩余验收的条件

配置SUPABASE_URL、SUPABASE_SERVICE_ROLE_KEY、SUPABASE_STORAGE_BUCKET、MEMORY_BACKUP_DIR和独立的MEMORY_BACKUP_KEY（不要发到聊天）。然后在专用私有桶用合成图片执行上传/跨用户拒绝/替换/删除，制作实际独立副本，在另一空私有桶恢复并逐对象核对。未完成这些操作前，本报告持续保持“核心通过、云端与独立恢复待验收”。
