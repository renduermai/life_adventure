# 朋友搭子

在「闪光的回忆」中进入「朋友搭子」，填写姓名、当前 Base 地和关系。Base 地可填常驻城市或地区。相处经历可以记在「珍贵时刻」、备注或事件时间线中。保存人物不会调用模型。

点击「重新读取」并确认后，系统通过灵石区对每位朋友分别分析。首次没有真实相处材料时提示依据不足。分析材料包括珍贵时刻前 1500 字符、备注前 800 字符及最近五条事件各前 650 字符。单独保存的姓名和 Base 地字段不传给模型，自由文本中自行填写的人名或地点可能包含在节选里。

五层图中每人只显示一个散点，落在记录支持的最高编号层。例如同时涉及 L1 和 L4 时，只在 L4 显示。仅当可信度和共鸣度两轴均有原文依据，四象限才显示散点。图上错开的点用于减少遮挡，点开可查看实际分值和说明。分值代表模型对现有记录的判断，不是对人的客观评级。电脑可悬停查看姓名，手机可轻触散点。

相关原文、提示词和模型配置一致时复用缓存。资料更新后旧点标为待更新。单人失败保留旧位置，下次「重新读取」可继续重试。现有灵石区速率限制适用，若短时间内有大量新增记录，可稍后再次读取。

## 幸运值

列表按幸运值从高到低排列，同分时最近新建的记录优先。幸运值满分 100，可信度占 40%，共鸣度占 30%，相处文字所体现的体验占 20%，五层图最高编号的换算分占 10%（L1 至 L5 对应 20 至 100 分）。文字部分依据实际支持或消耗等体验，不按字数计分。缺少任何必要依据时显示「待评估」，排在有分值的朋友后面。旧版分析首次点击「重新读取」后可补算。资料更新后显示已有分数并标「待更新」。

## 存储与恢复

0035 在 memory_people 增加 kind、base_location、friend_mapping，复用 memory_person_events 保存朋友事件。旧记录以原分类继续读取，旧人物分析仍使用 memory_person_analyses。完整 PostgreSQL 备份包含朋友资料、事件与已保存映射，恢复流程见 [RECOVERY.md](RECOVERY.md)。若已存在朋友资料，迁移脚本拒绝降级，避免丢失 Base 地、关系映射或人物分类。

生产迁移已核对 3 条旧人物、1 条旧事件、2 条旧分析的原字段摘要一致。
