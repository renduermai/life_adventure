# 精神导师：人物与分析（第2、3步）

人物分析现采用紧凑输出，当前百炼DeepSeek单独关闭思考、预算8192，其他AI用途不变。旧成功分析仍保留；重新预览并确认可使用新配置。真实合成验证、Token用量及限制见[截断最小修复](PERSON_ANALYSIS_MINIMAL_FIX.md)。

进入 `/shining-memories/people`，登录原有角色账号后使用。物品、心愿功能没有在本轮开发；图片Storage配置及异地图片恢复仍待准备，不影响人物记录。

## 人物和时间线

「添加人物」填写姓名、关系，选填珍贵时刻、最近联系日期、联系意愿和备注。未知日期留空，不能自动补成今天。卡片可查看、编辑和确认软删除。

选择人物后，添加有日期的事件。默认是回忆；明确勾选「这是一次实际联系」才参与联系日期计算。事件可编辑和软删除，用户录入原文不会被AI改写。事件按日期倒序，每次20条，继续加载可读历史。

最近联系日期 = 手填日期与有效实际联系事件中的最新日期。补录旧事件不会倒退最近日期；删除或将实际联系改成回忆后重新计算。日期不能晚于用户所在时区的今天。人物版本随事件变化递增，避免过期编辑覆盖。

热度 = max(0,100×(1−间隔天数/1095))，四舍五入为整数。无日期显示「暂无联系时间」；只表示时间新鲜度，不衡量感情。

## AI授权、预览和保存

选择人物 → 按需勾选「允许参考主线、副本」或「允许参考杂念」 → 输入关键词查找候选并选择具体记录 →「预览发送范围」→ 核对模型、文本及事件窗口 → 勾选外部模型传输确认 →「确认并分析」。默认不发任务和杂念，没有后台自动分析或自动重试。

人物姓名、关系、珍贵时刻、备注与最近10条事件会进入预览。较早事件明确标示未发送，不假装已分析全部历史。主线、副本、杂念各类最多5条，全文与人物文本总上下文超过容量时明确拒绝，不静默截断原文。候选列表摘要只用于选择，实际发送全文以预览为准。

预览包含人物、事件、来源文本、模型配置版本及提示版本指纹。预览后发生变化则要求重新预览；发布前再复核。模型输出经过Pydantic、来源ID和逐字引用校验，不能链接未授权、其他用户或已删除来源。来源后续被删除时，旧分析标记过期、隐藏无效链接。相关杂念通过受认证的note_id链接打开具体原文。

模型失败保留上次成功分析；页面显示最近错误码与旧结果是否过期。GET读取不调用模型。内容、范围和模型配置不变时复用缓存。用户更改范围后可重新分析；回到旧范围也可复用对应缓存。旧结果不改原始人物、任务或杂念，不自动联系人物。界面「忽略这条建议」只隐藏当前展示，重新进入可能再次显示，不会修改原始关联记录。

## 推荐联系指数 contact-v1

AI提取none/some/strong及原文依据，Python负责计分，AI不能返回任意分数。

| 因素 | 分值 |
|---|---|
| 人物意义 | 0 / 15 / 30 |
| 当前交流话题 | 0 / 10 / 20 |
| 已授权目标关联 | 0 / 10 / 20 |
| 联系间隔 | 未知或不足30天：0；30–179天：5；180–364天：10；365天及以上：15 |
| 明确愿意联系 | 15；其他0 |
| 负面影响 | 扣0 / 20 / 40 |

总分限制0–100；「犹豫」最高40；「暂不考虑」不参与推荐；原文支持明确暂缓边界时不参与推荐。人物意义、话题和目标均无足够信息时显示待评估，不能只凭联系间隔推高分。无日期不给间隔分。分数明细与引用可展开查看。

默认已评估按分数降序，待评估/过期结果在后，暂不考虑/暂缓再后；跨分页排序在服务端完成。分数是主观辅助，不是科学测量或关系成功概率。

## 数据与接口

0023_memory_people：人物、事件表；0024_person_analysis：分析历史表。所有记录有用户归属，事件与分析通过复合外键约束同一用户。软删除保留历史，不做破坏性清理。

- GET/POST `/api/shining-memories/people`；GET/PATCH/DELETE `/{person_id}`。
- GET/POST `/{person_id}/events`；PATCH/DELETE `/{person_id}/events/{event_id}`。
- GET `/api/shining-memories/people-sources?kind=quest|task|note&q=关键词&offset=0`。
- POST `/{person_id}/preview`：独立授权开关及所选UUID列表，不调用模型。
- GET/POST `/{person_id}/analysis`：读取旧分析/确认发起分析。POST必须有preview_token、consent_external=true和新的request_id。

新建人物、事件使用request_id幂等，编辑和删除携带expected_version。同源写入、长度及类型检查在服务端执行。分析缓存和错误独立保存，状态不覆盖成功原文。

现有应用JSON/CSV导出尚不包含人物与分析表，需要完整数据库备份覆盖memory_people、memory_person_events、memory_person_analyses及其身份/来源记录；数据库不包含Storage图片对象。不要只复制浏览器缓存或认为本机迁移检查点是独立备份。
