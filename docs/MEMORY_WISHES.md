# 心愿单：第5步

入口 `/shining-memories/wishes`，登录原有账号使用。支持新增、编辑、删除、类别筛选、可选私有图片和价格历史。价格统一人民币，均为用户手动估价；不联网查询行情或自动购买。

## 价格与故事

新增时写入首次价格、当前价格及一条initial历史。编辑描述、原因和类别不会改价格。详情中「保存价格」追加update历史，记录旧值、新值及时间。请求UUID幂等，重复请求不重复追加；修改携带版本检查，避免覆盖并发更新。

「这是纠正首次录入错误」需填写原因并二次确认。追加correction历史，保留最初initial原记录和纠正前值；修改首次比较基准。如果此前没有update记录，当前价也一并纠正；已有update时保留最新估价。故事明确显示「纠正后的首次价格」。历史不提供覆盖或删除接口，心愿删除采用软删除并保留价格记录。

Python Decimal计算首价与最新价的差额和百分比，按两位小数显示。上涨显示上涨；首价为零时比例无法计算；只有首次记录时显示暂无价格变化记录。创建日期按账号时区显示，故事由数据库事实和原始原因拼成，未填写原因明确说明，不调用AI生成故事。

## 分类与图片

「AI 分类」每次主动确认：只把该条心愿的名称、描述、想拥有的原因发送至灵石区当前配置的外部模型。图片、价格、主副本和杂念均不发送。Gateway用途为wish_category，JSON Schema校验后保存类别及简短依据，用户可在编辑中手动调整。相同文本、模型和提示版本可复用缓存；手动改类别后再次点击AI分类表示允许重新采用模型类别。失败保留原类别，并展示最近错误。过程中正文、类别或模型发生变化则拒绝过期结果，不自动重试。

无模型时，手动分类、浏览和价格更新仍可用。测试只使用合成账号和合成心愿，不发送真实私人记录。模型调用可能计费，实际开发Token及费用无法准确获取。

图片复用Supabase私有资产，服务端按所属用户读取。物品与心愿间禁止共享同一图片资产；关联中的图片不能绕过业务接口单独删除。替换先上传新的独立资产，再事务更新心愿引用，成功后旧资产进入延迟清理；删除心愿同样延迟清理图片。原记录及图片在上传失败时保留。

Storage未配置则明确提示，不回退到本地保存；允许无图新增。上传成功后业务保存失败时，当前页面保留已上传资产供重试；关闭页面可能留下未关联对象，需人工核对清理。没有自动备份调度。

## 数据、接口与备份

0026_memory_wishes新增memory_wishes、memory_wish_prices、memory_wish_classifications。都有用户归属，价格/分类通过用户和心愿复合外键约束，图片引用也同用户。价格为Numeric(14,2)且非负，分类历史与失败独立保存。

- GET/POST `/api/shining-memories/wishes`
- GET/PATCH/DELETE `/{id}`
- GET/POST `/{id}/prices`（分页读取历史/追加估价）
- POST `/{id}/initial-price-correction`（带原因纠正首价）
- POST `/{id}/classify`（request_id、expected_version、consent_external=true）

原JSON/CSV应用导出尚未包括心愿表；完整备份应包含整个应用数据库、代码迁移和独立图片备份。图片归档兼容到0026，不因新增心愿表拒绝旧图片快照。Supabase数据库备份不包含实际图片对象；本机迁移检查点也不等于异地备份。

## 验收说明

第5步已实施价格边界、历史幂等与纠错、用户隔离、跨模块图片保护、分类缓存与超时保留测试，以及真实默认模型合成分类与实际Edge价格流程。首次测试发现纠正后的金额未统一两位小数，已修正后重跑。详细计数见ACCEPTANCE.md。

Storage和异地备份配置仍未准备：真实Supabase图片上传、替换、删除、匿名访问拒绝和独立恢复尚未验收；可控存储替身不能当作真实云端通过。第6、7步未授权，本步完成后停止待验收。
