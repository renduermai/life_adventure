# 第 8 步：AI 拆解与执行联动

本步实现代码及数据库迁移为 `0012_breakdown`。最终验证结果见 ACCEPTANCE.md / PROGRESS.md 最新记录。第 9 步整体联调、V2 导出范围和跨设备验收不在本步内。

## 使用

1. 在主线或副本列表、详情点击「拆解」。页面加载目标及已确认状态，首次点击触发明确的生成请求；已有方案优先复用。直接访问启动状态 URL、刷新和历史切换不会重新消耗模型额度。
2. 右侧进入该目标的拆解区域，展示行动步骤、预计分钟数（估计）和完成标志，并标出最小启动动作。无已确认状态时如实说明；可先用左侧滑杆确认。
3. 可以反馈「第一步还是太难」「只有十分钟」再生成，也可修改标题、说明、耗时、完成标志和最小动作。字段修改后先点击「保存草稿修改」。
4. 勾选想保留的步骤，选择保存方式，点击「确认保存所选步骤」。生成或编辑草稿不会新建正式任务。
5. 如提示相似内容，可在步骤中选择已有项目复用、减少选择，或明确勾选允许重复。相似检查是辅助提示，不保证识别所有语义相近内容。
6. 保存后点击「进入第一步专注」。进入原有专注页面后，再点击开始计时。主线清单/里程碑可选择已有副本；没有合适副本时，明确点击「确认创建第一步副本并进入专注」。
7. 返回原任务查看正式保存内容；拆解历史可切换旧方案，重新生成不会覆盖已保存方案和正式对象映射。

## 保存规则

| 目标 | 支持的保存形式 | 执行关联 |
|---|---|---|
| 未完成主线 | 关联副本、里程碑、行动清单 | 已保存副本、选择已有副本，或明确创建最小副本 |
| 未完成普通根副本 | 一层子任务、行动清单 | 子任务或原副本 |
| 重复副本 / 已有子任务 | 行动清单 | 当前副本，不生成孙任务，不改变重复规则 |
| 已完成目标 | 可查看和讨论，保存清单 | 已完成副本不能计时；先在原页面处理 |
| 已删除、无权限或关联不可用 | 拒绝操作，给出提示 | 无 |

清单勾选只保存辅助步骤状态及操作记录，不修改原任务描述、不推进任务完成、不发奖励。正式任务创建通过 `tasks.service.execute`；里程碑创建抽取原路由逻辑为共享 `quests.service.create_milestone`，保留原事件记录。

用户在反馈中描述新的压力/能量时，模型只能提出待确认建议。点击载入、调整并确认后才保存快照。状态变化会让旧草稿过期，保存步骤前需要重新拆解。

## 数据与防重复

新增 `breakdown_plans`，保存用户/目标归属、请求指纹、上下文指纹、状态快照、历史方案关联、反馈、结构化草稿、模型调用来源、修订号、确认指纹、正式对象映射、执行副本关联、清单状态与操作记录。步骤 UUID 由服务器生成，模型不能自选业务对象 ID。

- 相同生成请求只重读原结果。进入已存在方案的目标时优先展示历史，不反复调用模型。
- 生成使用短事务预留记录，外部 AI 调用在事务外完成；发布前复查目标、状态和原草稿版本。迟到回复不能覆盖人工修改。
- 确认在用户锁保护的同一事务内执行全部创建。第二步失败时第一步也回滚。
- 同一方案重复确认只返回原映射；不同内容二次确认被拒绝。跨方案相似标题按规范化文本及相似度提示，可明确复用或允许重复。
- 已确认方案只允许清单勾选和执行关联；不再编辑正文。重新生成建立新方案，保留旧记录。
- 清单更新有请求幂等与独立版本；每份清单保留最多1000次勾选记录，达到上限明确拒绝，不静默丢弃审计。

状态快照新增同用户 `source_plan_id` 外键。关联状态与计划存在双向引用，因此未来清理/删除需要按外键顺序处理；应用不提供硬删除计划接口。

## 接口

| 接口 | 功能 |
|---|---|
| `GET /api/startup/breakdowns?task_type=...&task_id=...&offset=0` | 当前目标方案历史，20项/页 |
| `GET /api/startup/breakdowns/{id}` | 读取方案，重新校验目标权限与有效性 |
| `POST /api/startup/breakdowns` | 生成；带 previous_id / expected_revision / feedback 时继续调整 |
| `PATCH /api/startup/breakdowns/{id}` | 编辑未确认草稿 |
| `POST /api/startup/breakdowns/{id}/confirm` | 确认选中步骤、保存方式和复用选择 |
| `PATCH /api/startup/breakdowns/{id}/checklist` | 勾选清单，不触发任务/奖励命令 |
| `POST /api/startup/breakdowns/{id}/start` | 校验/准备真实执行副本，返回原 `/focus?task=UUID` 链接 |

请求使用既有认证、同源验证和32KiB输入限制。AI 统一走灵石区 `breakdown` 用途；该用途输出预算为1536 tokens。后续推荐可靠性改进也将 `task_analysis` 调至1536，其余用途仍为512。连接仍限制10秒，响应等待使用剩余60秒总预算，避免非流式长回复被连接超时提前截断。最多5步，预计时长1–240分钟；仅发送必要目标、最多20项已有结构、最近最多3份方案和当前反馈，长上下文进一步裁减旧方案。
